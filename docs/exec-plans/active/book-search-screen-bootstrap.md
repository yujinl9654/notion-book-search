# Book Search Screen Bootstrap Plan

## 목표

이미 정의된 feature 문서와 harness 케이스에 맞춰 첫 도서 검색 화면을 구현 가능한 상태로 가져갑니다.

## 입력 문서

- `docs/project-guide.md`
- `docs/product-specs/book-search-screen.md`
- `docs/harness/book-search-screen.md`

## 이미 결정된 사항

- 프론트엔드 스택은 `Vite + React`입니다.
- 스타일링은 Tailwind CSS를 사용합니다.
- 첫 데이터 소스는 목 데이터입니다.
- 기본 품질 게이트로 `eslint`와 `vite build`를 사용합니다.

## 현재 완료된 항목

- Vite 기반 React 앱 셸을 생성했습니다.
- Tailwind CSS와 ESLint 구성을 추가했습니다.
- 목 데이터 기반 검색 UI와 상태 전환을 구현했습니다.
- Node 버전은 `.nvmrc`의 `24.15.0`으로 고정했습니다.
- GitHub 원격 `origin`을 연결했습니다.

## 권장 순서

1. 첫 구현 스택을 정합니다.
   - 프론트엔드 프레임워크와 패키지 매니저를 고릅니다.
   - 첫 마일스톤을 목 데이터로 시작할지, 실제 도서 API로 시작할지 정합니다.
2. 가장 작은 실행 가능한 앱 셸을 만듭니다.
   - 검색 입력창, 실행 수단, 상태 표시 영역이 있는 페이지를 만듭니다.
3. 상태 모델부터 구현합니다.
   - 시각적 다듬기보다 먼저 idle, loading, success, empty, error 상태를 지원합니다.
4. 결과 렌더러를 연결합니다.
   - 최소한 제목은 노출하고, 선택적 메타데이터 누락을 안전하게 처리합니다.
5. harness 기준으로 수동 검증합니다.
   - `BOOK-SEARCH-001`부터 `BOOK-SEARCH-010`까지 확인합니다.
6. 첫 자동화 테스트를 추가합니다.
   - harness 문서에 적은 첫 자동화 후보부터 시작합니다.

## 첫 구현 완료 기준

- 사용자가 눈에 보이는 입력창과 실행 수단으로 검색을 시작할 수 있습니다.
- 화면이 로딩, 성공, 빈 결과, 오류 상태를 분명하게 지원합니다.
- 선택적 필드 누락이 결과 렌더링을 깨뜨리지 않습니다.
- 문서화된 P1 harness 케이스를 실행 중인 앱에서 수동으로 확인할 수 있습니다.

## 아직 필요한 결정

- 검색 데이터 소스
- 결과 선택 액션을 첫 마일스톤에 넣을지 여부

## 메모

첫 슬라이스가 끝까지 안정적으로 동작하기 전에는 범위를 넓히지 않습니다. 지금 필요한 첫 승리는 작은 도서 검색 화면과 명시적인 회귀 방지 기준입니다.
